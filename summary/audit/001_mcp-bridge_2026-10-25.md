# 001 · MCP-мост к OpenMontage отсутствует

**Дата:** 2026-10-25 · **Штамп:** mcp-bridge · **Задача:** [T001](../tasks/001_mcp-bridge_2026-10-25.md)

## Текущее состояние
OpenMontage — instruction-driven система без MCP-сервера: агент читает `pipeline_defs/*.yaml`
и директорские скиллы, а вызывает тулы через `tools/tool_registry.py`. Внешний агент
(Hermes / Bb / Claude Code / pi / OpenCode) не может вести проект — нет доступа к стадиям,
чекпоинтам, артефактам и гейтам.

MCP работает в другую сторону, «агент → студия»: ComfyUI, DaVinci Resolve, CapCut, Voicebox,
LeronX, Codegraph (`~/.pi/agent/mcp.json`, `.agents/mcp_config.json`, `opencode.jsonc`).

## Что зафиксировано
- Реестр: **158** тулов — **45** available, **109** unavailable, **4** degraded
  (`comfyui_image`, `comfyui_video`, `comfyui_music`, `corpus_builder` — локальные серверы не подняты).
  Третий статус важен: degraded ≠ недоступен, и в тестовом окружении (с заблокированными
  исходящими сокетами) часть degraded переходит в unavailable — счётчик плавает.
- Composition runtimes: ffmpeg + remotion + hyperframes — **3/3** доступны.
- **13** пайплайнов в `pipeline_defs/`; стадии, гейты и quality gates — только в YAML.
- Проектный контур целиком на диске: `projects/<id>/` (artifacts, assets, renders,
  checkpoint_*.json, decision_log.json, events.jsonl, history/); доска — `backlot` (HTTP + SSE).
- Дизайн моста зафиксирован в `OpenMontagMCP.md`.

## Состояние на 2026-10-25 (после T001)
Read-only мост **реализован**: `lib/mcp_bridge.py` + `scripts/openmontage_mcp.py`,
11 тулов, зарегистрирован в pi / Claude Code / Gemini CLI / OpenCode,
27 тестов контракта + смоук через настоящий MCP-клиент. Подробности — в
[summary/tasks/001](tasks/001_mcp-bridge_2026-10-25.md).

## Риск
Внешние агенты идут в обход системы: пишут ассеты мимо workspace, теряют гейты
и аудит решений, дублируют платные генерации.
