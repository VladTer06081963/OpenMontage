# summary

Краткий аудит состояния OpenMontage и парные задачи на исправление / доработку.

## Структура

    summary/
    ├── audit/    NNN_<штамп>_<YYYY-MM-DD>.md   — текущее состояние (что есть, что зафиксировано, риск)
    └── tasks/    NNN_<штамп>_<YYYY-MM-DD>.md   — задачи на исправление / доработку

## Соглашение об именовании

`NNN_<штамп>_<дата>.md`

| Часть | Значение |
|---|---|
| `NNN` | сквозной номер пары, **одинаковый** в `audit/` и `tasks/` (001 ↔ 001) |
| `<штамп>` | короткий слаг темы, kebab-case, латиница (`mcp-bridge`, `budget-tracker`) |
| `<дата>` | `YYYY-MM-DD` — дата фиксации состояния |

## Правило паритета

Аудит `NNN` ↔ задача `NNN` — одна пара, файлы называются одинаково.

Если на один аудит нужно несколько независимых задач, дополнительные файлы получают
**префикс `T` и буквенный суффикс**:

    audit/001_mcp-bridge_2026-10-25.md
    tasks/001_mcp-bridge_2026-10-25.md        <- основная
    tasks/T001_a_mcp-bridge_2026-10-25.md    <- дополнительная
    tasks/T001_b_mcp-bridge_2026-10-25.md    <- дополнительная

В таком случае в разделе «Связанные задачи» аудита перечисляются **все** файлы пары.
Обратное тоже верно: если задача выросла из нескольких аудитов, она получает префикс `T`
с номерами соответствующих аудитов (`T003_T004_...`).

## Шаблон аудита

- **Дата / штамп / задача** — шапка с ссылкой на парный файл задачи
- **Текущее состояние** — 3–5 строк о том, что есть сейчас
- **Что зафиксировано** — проверяемые факты со ссылками на код (`file:line`)
- **Риск** — что ломается, если не чинить
- **Связанные задачи** — ссылки на все файлы пары

## Шаблон задачи

- **Дата / штамп / аудит** — шапка с ссылкой на парный файл аудита
- **Цель** — одна фраза
- **Что сделать** — нумерованный список шагов
- **Готово, когда** — чекбоксы с критериями приёмки (желательно с пометкой «тест»)

Подробности архитектуры и полная спецификация моста — в `OpenMontagMCP.md`.
